# **Stellar Blade — Hypertube Advisor**

## **Дополнение к контексту: Actor identity в Advisor**

**Дата:** 13 ноября 2026\
**Последний разобранный лог:** LOG V12\
**Текущий статус:** изменение кода внесено пользователем, но ещё не протестировано.

### **1. Что исследовали**

Пользователь предоставил ссылку на фрагменты кода:

[GitHub — Fragment V6](https://github.com/XeXxDD/EveHyberTrube/blob/main/Fragment%20V6?utm_source=chatgpt.com)

Наша задача состояла в том, чтобы связать два вывода:

- `[LOCAL-GEOM]` — диагностическая геометрия конкретного препятствия.
- Основной Advisor — объект, который он считает опасным (`DANGER-INSIDE`, `WILL-ENTER` и другие статусы).

Проблема заключалась в том, что Advisor выводил только класс объекта, но не имя конкретного Actor. Например, класс `BP_ContainerTrain_Box_C` может соответствовать множеству разных ящиков.

### **2. Что обнаружили в коде**

При изучении Fragment V6 выяснилось:

**Имя Actor уже сохранялось в&#x20;**`closestObs`**.**

В `HTS:OBSTACLE_SCAN` присутствовало:

```
closestObs = {
    name = actor:GetFName():ToString(),
    cls = adv_safeCall(actor:GetClass(), "GetFName"):ToString(),
    dist = effectiveFwd,
    ttc = ttc,
    minTheta = minTheta,
    maxTheta = maxTheta,
```

То есть дополнительное сохранение имени не требовалось.

В `HTS:LOCAL_GEOM_AUDIT` использовался тот же способ получения имени:

```
local objectName = actor:GetFName():ToString()
```

Таким образом, оба механизма используют один источник идентификации.

### **3. Какое изменение внесено**

Пользователь сообщил о внесении изменения

Менялась только одна строка в `HTS:ADVISOR_OUTPUT`.

Старая версия:

```
print(string.format("\n[%s] %s %s | Dist=%.0f | TTC=%.2fs\n", ADV_MOD, status, closestObs.cls, closestObs.dist, closestObs.ttc))
```

Предложенная новая версия:

```
print(string.format("\n[%s] %s %s | Actor=%s | Dist=%.0f | TTC=%.2fs\n", ADV_MOD, status, closestObs.cls, closestObs.name, closestObs.dist, closestObs.ttc))
```

Добавлен один placeholder `%s` и соответствующий аргумент `closestObs.name`.

**Других изменений не планировалось.**

Не меняли:

- выбор ближайшего препятствия;
- старую систему координат Advisor;
- Sector и RadCenter;
- TTC;
- PredTheta и Omega;
- рекомендации A/D;
- LOCAL-GEOM.

### **4. Что ожидаем увидеть**

Раньше:

```
[DANGER-INSIDE] BP_ContainerTrain_Box_C | Dist=3059 | TTC=0.68s
```

Теперь:

```
[DANGER-INSIDE] BP_ContainerTrain_Box_C | Actor=BP_ContainerTrain_Box92_32 | Dist=3059 | TTC=0.68s
```

Это пример ожидаемого формата, не результат проведённого теста.

В `[LOCAL-GEOM]` уже должно присутствовать имя того же объекта:

```
[LOCAL-GEOM] BP_ContainerTrain_Box92_32 | ...
```

Таким образом, мы сможем сопоставить две записи одного физического препятствия.

### **5. Что необходимо сделать в новом чате**

Первым делом получить тестовый лог после внесённого изменения.

Использовать стандартную последовательность:

1. Запустить игру и скрипт.
2. Нажать F3.
3. Дождаться `TUBE DETECTED` и `INDEX READY`.
4. Включить Advisor через NumPad `*`.
5. Выполнить стандартный маршрут до первого полного кругового манёвра.
6. Отключить Advisor.

После получения лога:

- Найти строки `[DANGER-INSIDE]` и `[WILL-ENTER]`.
- Выписать имена Actor.
- Найти соответствующие строки `[LOCAL-GEOM]`.
- Сопоставить параметры одного и того же объекта.

Особенно интересуют:

- старые `Sector` и `RadCenter` Advisor;
- `LocalSector` и `RadCenter` LOCAL-GEOM;
- `Dist`, `SplineDelta`, `EveTangentFwd`;
- `TangentDiff`;
- `MinRotTwist`;
- `DeltaThetaEveMinRot`.

### **6. Главная цель следующего этапа**

Пока не исправлять старую геометрию Advisor.

Сначала необходимо установить, насколько сильно различаются две системы координат при расчёте одного и того же препятствия.

Только после этого можно будет исследовать корректный перенос локального базиса вдоль сплайна и решать, как преобразовывать локальную геометрию препятствия в систему координат Евы.

**Итоговое состояние:** изменение состоит из одной строки в `HTS:ADVISOR_OUTPUT`. Пользователь его уже внёс, но работоспособность пока не подтверждена игровым тестом. Следующее действие — получить лог и проверить, совпадают ли имена Actor в двух диагностических системах.
